01

CRM vs ERP

Que veut dire CRM ? Et ERP ?
CRM = Customer Relationship Management (gestion de la relation client, avant la vente). ERP = Enterprise Resource Planning (planification des ressources de l'entreprise, après la vente : compta, stock).
Le stock de produits en entrepôt : CRM ou ERP ? Pourquoi ?
ERP. C'est une ressource interne de l'entreprise, indépendante de la relation avec un client précis — rien à voir avec une négociation commerciale.
À quel moment précis bascule-t-on du CRM à l'ERP dans ce projet ?
Quand le deal HubSpot passe au statut "Closed Won" — le signal que la vente est actée, et que le relais doit être pris côté gestion/comptabilité.

02

HubSpot & API

Que signifie "Closed Won" ?
Le deal est clos ("Closed") et gagné ("Won") — le contrat est signé.
Pourquoi le deal HubSpot ne contient-il pas directement le nom ou l'email du client ?
Un deal est relié à un Contact/une Entreprise via un lien séparé, une association — pas fusionné dans le même enregistrement. Il faut un appel séparé pour récupérer les infos du contact.
Pourquoi utiliser /deals/search (POST) plutôt qu'un simple GET liste ?
L'endpoint de recherche permet de filtrer (dealstage = closedwon) ET de trier (par date de modification) directement côté serveur, plutôt que de tout récupérer et filtrer après — plus économe en appels API (rate limiting).
Pourquoi a-t-on besoin d'un deuxième appel HTTP pour connaître le nom/email du client ?
Le premier appel ne donne que l'ID du contact associé. Il faut un second appel GET sur cet ID précis pour récupérer ses propriétés (firstname, lastname, email).
Comment savoir s'il faut utiliser GET ou POST ?
GET = on demande/lit une info, rien ne change côté serveur. POST = on envoie des données pour créer/déclencher une action. La recherche de deals est en POST car HubSpot a besoin qu'on lui envoie un corps JSON avec les filtres.

03

n8n — mécaniques

Différence entre polling et webhook ?
Webhook = la source (HubSpot) prévient automatiquement. Polling = on va soi-même demander à intervalle régulier. On a utilisé le polling ici car la clé de service HubSpot choisie ne proposait pas de configuration de webhook.
Pourquoi parfois $json ne suffit pas et il faut écrire $('NomDuNoeud').item.json... ?
$json référence toujours la sortie du nœud immédiatement précédent. Dès qu'on enchaîne plusieurs appels, chaque nouveau nœud le remplace. Pour retrouver une donnée d'un nœud plus ancien, il faut le référencer explicitement par son nom.
À quoi sert le nœud Merge dans le workflow ?
À réunir deux chemins alternatifs (client neuf créé, ou client déjà existant retrouvé) en une seule sortie commune, pour que la suite reçoive toujours la même forme de donnée peu importe le chemin emprunté.
Pourquoi le nœud IF anti-doublon vérifie result.length === 0 ?
La recherche renvoie une liste de résultats. Vide (longueur 0) = rien n'existe encore, on peut créer. Non vide = quelque chose existe déjà, on s'arrête.

04

Odoo & JSON-RPC

Pourquoi Odoo n'utilise pas une API REST classique comme HubSpot ?
Odoo (Community, sans module REST additionnel) expose son API via JSON-RPC : chaque appel dit "appelle telle fonction, avec tels arguments", plutôt que de simplement consulter une URL.
Que représentent res.partner, sale.order, account.move ?
res.partner = fiche client. sale.order = commande. account.move = facture (et plus largement, écriture comptable).
Pourquoi l'appel à _create_invoices a-t-il été refusé par Odoo ?
Le underscore en préfixe signifie "méthode privée, réservée à l'usage interne" — Odoo bloque volontairement l'appel de méthodes privées depuis l'extérieur, par sécurité.
Par quoi a-t-on remplacé cet appel ?
Par une création directe de l'objet account.move (facture), une méthode publique standard, plutôt que de passer par le mécanisme interne de la commande.
Pourquoi une ligne de commande a besoin d'un product_id, pas juste d'un texte libre ?
Une contrainte de la base de données Odoo exige qu'une ligne "facturable" soit reliée à un vrai produit avec une unité de mesure — sinon elle n'est pas considérée comme comptabilisable.

05

Infra — Docker, VPS, réseau

Pourquoi a-t-on dû déplacer Odoo du Mac vers le VPS ?
n8n tournait à distance, sur le VPS. "localhost" depuis le VPS désigne le VPS lui-même, pas le Mac — n8n ne pouvait donc pas atteindre l'Odoo qui tournait en local.
Pourquoi deux conteneurs séparés (Odoo + Postgres) plutôt qu'un seul ?
Séparation des responsabilités : on peut mettre à jour/redémarrer Odoo sans toucher à la base de données, et on réutilise l'image Postgres officielle plutôt que de réinventer la gestion de base.
Que fait Traefik dans cette architecture ?
C'est le "réceptionniste" du serveur : il regarde le nom de domaine demandé et redirige vers le bon conteneur, en gérant aussi automatiquement le certificat HTTPS (Let's Encrypt).
Pourquoi le certificat HTTPS a-t-il échoué au premier essai ?
Traefik a tenté d'obtenir le certificat avant que l'enregistrement DNS n'ait eu le temps de se propager sur Internet. Une fois le DNS confirmé, un redémarrage de Traefik a suffi.

06

Sécurité

Pourquoi ne jamais laisser un mot de passe en clair dans un fichier suivi par Git ?
Un dépôt versionné — surtout s'il devient public un jour — peut exposer ce secret définitivement dans l'historique. Des scanners automatiques parcourent GitHub en continu à la recherche de ce genre de fuite.
Comment le principe du moindre privilège a été appliqué sur la clé HubSpot ?
La clé de service créée n'a que 3 scopes en lecture seule (deals, contacts, companies) — jamais de droits d'écriture, alors que le workflow n'a besoin que de lire des informations côté HubSpot.

07

SQL

Que fait une jointure (JOIN) dans la requête SQL utilisée ?
Elle relie deux tables (account_move et res_partner) via une colonne commune (partner_id), pour afficher en une seule requête des informations qui vivent dans des tables séparées.
Pourquoi interroger Postgres directement plutôt que par l'API dans ce cas ?
Pour des besoins de vérification/reporting ponctuels, une requête SQL directe est souvent plus rapide et flexible qu'un enchaînement d'appels API — mais ça demande d'exposer un accès à la base, à faire avec précaution (isolation réseau en vraie prod).

08

Gestion d'erreur

Comment fonctionne le mécanisme d'Error Trigger de n8n ?
Ce n'est pas un nœud inséré dans le workflow principal — c'est un deuxième workflow séparé, contenant un nœud Error Trigger, désigné dans les Settings du workflow principal ("Error Workflow"). n8n le déclenche automatiquement, avec les détails de l'échec, si n'importe quel nœud du principal plante.
